Um grupo terrorista está a usar um software de troca de mensagens recorrendo a criptografia de chave simétrica para coordenar as suas operações. As forças de segurança não estão a conseguir interpretar as comunicações intercetadas, porque os atacantes estão a usar um mecanismo criptográfico forte.

Entretanto as autoridades resolvem recorrer a um especialista em cibersegurança (vocês) para tentar resolver este problema.

Os serviços de informações estão convencidos que uma das mensagens que conseguiram intercetar contém informação sobre um atentado planeado contra a Assembleia da República, incluindo o rapto de um conjunto de ministros e deputados, assim como a data e o local de concentração dos elementos do grupo. É de importância vital que as autoridades consigam ter acesso a esta informação para que possam montar uma operação de prevenção e proteção que impeça o ataque.

Há alguns tipos de informação a que as autoridades tiveram acesso, através de informadores internos:

O software de troca de mensagens funciona com base no algoritmo AES, em modo CTR, com chaves de 256 bits;
A mensagem cifrada é construída da seguinte forma: ao criptograma é anteposto, em claro, o vetor de inicialização (IV/nonce) de 16 bytes usado no modo CTR; o conjunto resultante (IV || criptograma) é depois codificado em Base64;
A mensagem começa com a seguinte frase "Ponto de encontro:", no entanto a restante mensagem é desconhecida;
O software foi escrito em Python e, por limitações de implementação, não gera a chave de 256 bits a partir de uma fonte de aleatoriedade segura. Em vez disso, no instante do envio, o software executa o equivalente a:
import random
random.seed(T)            # T = tempo Unix, em segundos, do instante do envio
key = random.randbytes(32)   # chave AES de 256 bits
ou seja, a chave é totalmente determinada pelo relógio do sistema (gerador pseudo-aleatório padrão do Python — Mersenne Twister — semeado com o tempo Unix em segundos);
